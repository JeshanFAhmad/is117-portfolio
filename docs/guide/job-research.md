## What the comparison shows

Both roles involve building AI-powered systems, integrating software, and working with other teams. The difference is the level and setting of responsibility.

The American Express AI Engineer I posting is structured for a new graduate. It emphasizes foundational programming and AI knowledge, supervised development work, testing, documentation, and collaboration. The Cognizant Forward Deployed Engineer posting expects at least five years of relevant experience and places greater emphasis on client discovery, cloud architecture, enterprise integration, and production delivery.

This comparison shows why job titles alone are not enough. A useful role comparison checks the actual tasks, experience requirements, location, deadline, and evidence requested by each employer.

## Turning job research into portfolio evidence

Use repeated requirements from the postings to plan projects. Do not claim a skill just because it appears in a job description; identify a project or course artifact that demonstrates it.

| Skill area | Possible evidence |
| --- | --- |
| Programming and object-oriented design | A documented application with readable code and tests |
| APIs and integration | A small application that retrieves and uses data from an API |
| AI and model evaluation | A limited AI prototype with test questions, expected results, and documented limitations |
| Data handling | A small data-cleaning or retrieval project with a clear explanation |
| Communication and documentation | A README explaining the problem, design decisions, tests, and limitations |
| Customer discovery | A fictional or consent-based workflow case study that identifies a user problem and evaluates a proposed solution |

A manageable first project is a small AI-assisted FAQ application using public or sample documents. Include a problem statement, a simple architecture diagram, source references, test cases, limitations, and a short explanation of what you would improve next.

## One-week research-to-portfolio plan

1. **Day 1:** Find two current employer postings for the role you want to explore.
2. **Day 2:** Complete one role card for each posting, including source, date checked, deadline, and availability.
3. **Day 3:** Highlight repeated technical and communication skills.
4. **Day 4:** Choose one small project that demonstrates two of those skills.
5. **Day 5:** Write a project outline with a user problem, planned features, and ways to test it.
6. **Day 6:** Ask a classmate to review whether the evidence is clear and believable.
7. **Day 7:** Record feedback, decide what to change, and commit the updated plan.

## Privacy and submission note

Keep personal eligibility circumstances and the full 250–350-word reflection in the private Canvas submission. Public GitHub documentation should contain source-backed job research, general role requirements, professional goals, and portfolio evidence—not private personal circumstances.

## Research quality checklist

- Link to the original employer description whenever possible.
- Record the date you checked the page.
- Separate minimum qualifications from preferred qualifications.
- Quote the employer's deadline wording or write “not stated.”
- Mark availability as open, closed, unclear, or not stated, and explain why.
- Do not infer sponsorship, eligibility, salary, or experience requirements that the employer does not state.
- Recheck time-sensitive details before using a posting to make a decision.
